# 配置系统简化说明

## 概述

v1.5.0 版本完全简化了配置和初始化流程：
- ✅ 单一配置文件：`config.py`
- ✅ 自动初始化脚本：`init.py`
- ✅ 智能环境检测：本地/云端
- ✅ 自动数据库迁移

## 对比

### 旧版本（v1.4.0 及之前）

```bash
# 1. 复制多个配置文件
cp .env.example .env

# 2. 编辑配置
vim .env

# 3. 手动创建数据库脚本
vim init_user.py

# 4. 运行初始化
python init_user.py

# 5. 手动运行迁移
python migrate_add_weekdays.py
python migrate_add_farewell_message.py

# 6. 修改代码中的硬编码
vim web/routes.py  # 修改 secret key
```

**问题**:
- ❌ 配置分散在多个文件
- ❌ 需要手动创建初始化脚本
- ❌ 需要手动运行多个迁移脚本
- ❌ 硬编码需要手动修改
- ❌ 环境切换复杂

### 新版本（v1.5.0+）

```bash
# 1. 复制配置文件
cp config_local.py.example config.py

# 2. 运行初始化向导
python init.py

# 完成！
```

**优势**:
- ✅ 单一配置文件
- ✅ 交互式初始化向导
- ✅ 自动检测并执行迁移
- ✅ 无硬编码，所有配置可配置
- ✅ 智能环境检测

## 初始化流程

### init.py（390 行）

自动完成以下步骤：

```
[1] 检查配置文件
    ├─ 检测 config.py 是否存在
    └─ 不存在则从示例文件创建

[2] 验证配置
    ├─ 检查必需的配置项
    ├─ 验证密码长度
    └─ 检查部署环境

[3] 初始化数据库
    ├─ 创建数据库和表
    └─ 检查并执行迁移

[4] 检查数据库迁移
    ├─ 添加 takeover_weekdays 字段（如果需要）
    └─ 添加 farewell_message 字段（如果需要）

[5] 初始化云湖账户
    ├─ 提示输入邮箱和密码
    ├─ 加密敏感信息
    ├─ 存储到数据库
    └─ 测试加密/解密

[6] 生成随机配置（可选）
    └─ 生成安全的随机密钥

完成！
```

## 安全改进

### 1. 密码提示输入

**旧版本**: 明文写在配置文件中

```python
# .env
YUNHU_EMAIL = "user@example.com"
YUNHU_PASSWORD = "password123"  # 明文密码
```

**新版本**: 可选的命令行输入

```python
# config.py（密码留空）
YUNHU_EMAIL = ""
YUNHU_PASSWORD = ""

# 运行 init.py 时通过命令行输入（不记录到文件）
# 这样更安全
```

```python
    if not ENCRYPTION_SALT:
        errors.append("ENCRYPTION_SALT 不能为空")
    
    # ... 更多验证
```

### 3. 随机密钥生成

```bash

```

## 常见问题

### Q1: 为什么移除 `.env`？

**A**: `.env` 文件容易出错：
- 需要手动调用 `load_dotenv()`
- 配置分散
- 类型不明确（都是字符串）

`config.py` 更好：
- 单一配置文件
- Python 语法支持（类型、注释）
- 自动验证
- 自动环境检测

### Q2: 如何生成安全密钥？

**A**: 使用 Python `secrets` 模块：

```bash
python -c "import secrets; print(secrets.token_urlsafe(16))"
```

### Q3: 修改配置后需要重启吗？

**A**: 
- `DEPLOYMENT_ENV`、路径配置：需要重启
- 其他配置：重启后生效

### Q4: 数据库迁移会丢失数据吗？

**A**: 不会。迁移脚本会：
- 保留所有现有数据
- 只添加新字段
- 调整字段类型（保留数据）
