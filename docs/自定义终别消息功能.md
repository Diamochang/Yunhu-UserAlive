# 自定义终别消息功能

## 概述

v1.3.0 版本新增了自定义终别消息功能,允许用户为每个信任的好友设置个性化的电子终别消息。

## 功能说明

### 默认行为

在未设置自定义消息时,系统使用默认的终别消息:

```
⚠️【电子终别】特别提醒：请在信封上写明你的名址，以免失去最后的联系。
```

### 自定义消息

用户可以为每个好友设置独特的终别消息,例如:

- **温馨版**: "亲爱的朋友,如果你收到这条消息,说明我已经很久没有上线了。请记得我们的约定,保持联系!"
- **诗意版**: "人生如逆旅,我亦是行人。愿你在云湖的世界里继续探索,找到属于自己的风景。"
- **简洁版**: "保重!期待再次相遇。"
- **幽默版**: "嘿!别难过,我只是去休个长假~ 记得想我哦!"

## 使用方法

### 方法一: Web 控制台(推荐)

#### 1. 添加好友时设置

在设置页面的"好友管理"部分:

1. 输入好友的 Chat ID
2. 输入备注名(可选)
3. 粘贴 OpenPGP 加密后的住址密文
4. **在"自定义终别消息"文本框中输入个性化消息**
5. 勾选"局部终别"(必须启用才能显示消息)
6. 点击"添加好友"

#### 2. 编辑已有好友的消息

在好友列表中:

1. 找到要修改的好友
2. 点击"自定义消息"列的"编辑"或"添加"按钮
3. 在弹出的对话框中输入新的终别消息
4. 点击"保存"

#### 3. 清空自定义消息

如果想恢复默认消息:

1. 点击"编辑"按钮打开对话框
2. 点击"清空"按钮
3. 确认操作

或者直接删除文本框中的所有内容并保存。

### 方法二: API 调用

```bash
curl -X POST http://localhost:5000/api/friend/farewell_message \
  -H "Content-Type: application/json" \
  -d '{
    "friend_chat_id": "12345678",
    "farewell_message": "这是自定义的终别消息"
  }'
```

**响应示例**:
```json
{
  "success": true,
  "message": "终别消息已更新",
  "farewell_message": "这是自定义终别消息"
}
```

**清空消息**:
```bash
curl -X POST http://localhost:5000/api/friend/farewell_message \
  -H "Content-Type: application/json" \
  -d '{
    "friend_chat_id": "12345678",
    "farewell_message": null
  }'
```

### 方法三: 数据库直接操作

```sql
-- 设置自定义消息
UPDATE friends 
SET farewell_message = '你的自定义消息'
WHERE user_id = 1 AND friend_chat_id = '12345678';

-- 清空自定义消息(使用默认消息)
UPDATE friends 
SET farewell_message = NULL
WHERE user_id = 1 AND friend_chat_id = '12345678';
```

## 触发条件

自定义终别消息只在以下条件同时满足时显示:

1. ✅ 好友发送关键词 **"住址"**
2. ✅ 该好友已启用 **局部电子终别标记** (`local_final_farewell = 1`)
3. ✅ 好友存在于信任好友列表中

## 消息格式

### 支持的格式

- ✅ 纯文本
- ✅ 换行符 (`\n`)
- ✅ Emoji 表情
- ✅ 特殊符号

### 不支持的格式

- ❌ Markdown 格式(会被当作纯文本)
- ❌ HTML 标签(会被转义)
- ❌ 富文本格式

### 长度限制

建议控制在 **200 字符以内**,过长的消息可能影响阅读体验。

## 数据库迁移

如果是从旧版本升级,需要运行迁移脚本:

```bash
python migrate_add_farewell_message.py
```

这会:
- 在 `friends` 表添加 `farewell_message` 字段
- 所有现有好友的该字段设为 `NULL`(使用默认消息)
- 不影响其他数据

## 技术实现

### 数据库结构

```sql
CREATE TABLE friends (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    friend_chat_id TEXT NOT NULL,
    friend_name TEXT,
    encrypted_address TEXT,
    local_final_farewell BOOLEAN DEFAULT 0,
    farewell_message TEXT,  -- 新增字段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    UNIQUE(user_id, friend_chat_id)
);
```

### 消息处理逻辑

```python
# yunhu/message_handler.py
if friend['local_final_farewell']:
    # 使用自定义终别消息，如果没有则使用默认消息
    custom_message = friend.get('farewell_message')
    if custom_message:
        farewell_msg = f"\n\n{custom_message}"
    else:
        farewell_msg = "\n\n⚠️【电子终别】特别提醒：请在信封上写明你的名址，以免失去最后的联系。"
```

### API 端点

- **POST** `/api/friend/farewell_message` - 更新好友的自定义终别消息

**请求参数**:
```json
{
  "friend_chat_id": "string",  // 必填: 好友的云湖ID
  "farewell_message": "string|null"  // 可选: 自定义消息,null表示使用默认
}
```

**响应**:
```json
{
  "success": true,
  "message": "终别消息已更新",
  "farewell_message": "string|null"
}
```

## 常见问题

### Q1: 为什么设置了自定义消息但没有显示?

**A**: 请检查:
1. 是否启用了"局部电子终别"标记
2. 好友是否通过"住址"关键词触发
3. 消息是否正确保存(刷新页面查看)

### Q2: 可以为所有好友设置相同的自定义消息吗?

**A**: 目前需要逐个设置。如果需要批量设置,可以使用 SQL:

```sql
UPDATE friends 
SET farewell_message = '统一的自定义消息'
WHERE user_id = 1 AND local_final_farewell = 1;
```

### Q3: 自定义消息会影响性能吗?

**A**: 不会。消息存储在数据库中,只有在好友查询住址时才会读取,对性能影响可以忽略不计。

### Q4: 消息中有特殊字符怎么办?

**A**: 系统会自动处理转义。在 Web 界面直接输入即可,无需手动转义。

### Q5: 如何备份自定义消息?

**A**: 备份整个数据库文件即可:

```bash
cp data/yunhu_useralive.db data/yunhu_useralive.db.backup
```

或者导出特定数据:

```sql
SELECT friend_chat_id, friend_name, farewell_message 
FROM friends 
WHERE farewell_message IS NOT NULL;
```

## 最佳实践

### 1. 个性化但不冗长

✅ 好的示例:
```
亲爱的朋友,感谢一路相伴。愿你前程似锦,我们后会有期! 🌟
```

❌ 避免:
```
[一篇500字的长篇大论...]
```

### 2. 考虑接收者的感受

✅ 温暖积极:
```
虽然我要离开了,但我们的友谊永存。继续保持热爱,奔赴山海!
```

❌ 避免消极:
```
再见了,这个世界没什么值得留恋的...
```

### 3. 提供后续联系方式(可选)

```
这是我的备用联系方式: email@example.com
有空常联系!
```

### 4. 定期检查和更新

建议每隔几个月检查一下终别消息,确保它们仍然符合你的心意。
